# Datasets

Every dataset the paper measures, how it is fetched, and exactly which subset
is used. Each subset follows a rule written down here, never a pick of tables
or rows by hand, and a change to a rule is a new artifact version, recorded
under [Subset history](#subset-history) with what prompted it.

No downloaded data is committed. Each dataset has a `fetch.sh` that downloads
or generates it into `datasets/data/` (or `$COLBIN_DATA`) and checks every file
against [`MANIFEST.sha256`](MANIFEST.sha256). Generated data (TPC-H) is pinned
by the generator's commit and by the checksum of its output.

```sh
datasets/fetch-all.sh            # everything
datasets/tpch/fetch.sh           # one dataset
cd datasets/data && sha256sum -c ../MANIFEST.sha256   # verify without the scripts
```

| dataset | source | subset measured | shape | licence (redistributed?) |
|---|---|---|---|---|
| `tpch` | TPC-H dbgen 2.17.3 (`gregrahn/tpch-kit@852ad0a`) | all 8 tables at SF 0.1 (timed); `Nested` is orders + lineitem only | `Nested`, `Normalized` | TPC EULA (no) |
| `tpcds` | TPC-DS SF 0.1, generated by DuckDB v2.0.0's bundled dsdgen pinned by URL in `fetch.sh` | all 24 tables at SF 0.1 (timed), one case per table | one row struct per table plus a `<Table>Table` wrapper holding its rows | generated locally, not committed (no) |
| `schemastore` | Viotti & Kinderkhedia's corpus (`jviotti/binary-json-size-benchmark@1075bc7`) | all 27 documents, typed and dynamic | one root per document, hand-written from their protobuf schemas | Apache-2.0 (not committed) |
| `publicbi` | Public BI Benchmark, CWI (`cwida/public_bi_benchmark@cf99090`) | `<workbook>_1` of all 46 workbooks, a seeded random sample of 16 384 rows | one root per table, generated from its CREATE TABLE | none stated for the data (no) |

Each dataset directory holds `LICENSE-NOTE.md` with the licence and whether
the data may be redistributed.

## What is evaluated, and the two regimes

colbin is evaluated here as a **serialization format compared in Go**: the
bytes a Go program writes and reads, against the other formats' Go
implementations. Its intended use is what a server sends a web client instead
of JSON, but decoding in a browser (WebAssembly against `JSON.parse`) is not
measured by this matrix, and the paper claims nothing about it.

That use bounds the size of a message: a response to a web client (a product
list, a sales report, an attendance report) rarely holds more than about ten
thousand rows. So every case falls in one of two regimes, by its row count
alone (`matrix.WebRows`, 16 384 = 2^14, that bound rounded up):

| regime | rule | cases |
|---|---|---|
| `web` | at most 16 384 rows | all 46 Public BI samples, all 27 SchemaStore documents (typed and dynamic), 16 of the 24 TPC-DS tables, 4 of the 8 TPC-H tables (region, nation, supplier, customer) |
| `bulk` | more than 16 384 rows | the other 8 TPC-DS tables and 4 TPC-H tables, and TPC-H's `Nested` and `Normalized` |

The two are reported apart (a `regime` column in `sizes.csv` and `cases.csv`,
a `regime:` configuration line before each case in the benchmark output), and
no summary pools them: the web regime is the one the intended use is judged
by, and the bulk regime shows how each format scales past it.

## How the subsets were chosen

- **TPC-H and TPC-DS: every table, at scale factor 0.1.** Nothing is left out
  at that scale. SF 0.1 is about 100 MB of text per benchmark, which every
  format holds in memory at once on one machine and on a 4 GB Lambda; a
  larger scale adds rows to the bulk regime only. Both generators draw from
  near-uniform distributions, which is a known weakness of synthetic
  benchmarks for encodings (Vogelsgesang et al., "Get Real", DBTest 2018);
  Public BI is here as the real-data counterweight.
- **TPC-H `Nested`** is orders with their lines: the only parent and child in
  the schema, so the only two tables a nested shape has.
- **Public BI: the first table of every workbook (`<workbook>_1`).** One table
  per workbook keeps any one workbook from weighing more than another. Of the
  46 workbooks, 20 have one table and 18 have several that share `_1`'s
  schema, so `_1` stands for the whole workbook; in the other 8 (Generico, MLB,
  Rentabilidad, SalariesFrance, TableroSistemaPenal, TrainsUK1, Wins,
  YaleLanguages) the further tables have other schemas and are not measured.
  `_1` is the rule because it is the one every workbook has, not because of
  anything in its data.
- **Public BI: a seeded random sample of 16 384 rows** of each table, or all of
  it where it is shorter (IUBLibrary_1 has 1 795 rows, TrainsUK1_1 has 1). The
  size is the web regime's bound. The rows are a simple random sample, not the
  head of the file: the tables are often sorted or grouped by their leading
  columns, so the head repeats values far more than the table does, which
  would flatter the formats that exploit repetition. The sample is bottom-k on
  a splitmix64 key of a fixed seed, the table's name and the row's index
  (`publicbi/subset`), so it depends on nothing but the seed and the data, and
  keeps the rows in table order.
- **SchemaStore: all 27 documents** of Viotti and Kinderkhedia's corpus, which
  they chose, not this repository. The six colbin cannot carry are reported
  as n/a with the reason, never dropped.

## Subset history

Each entry is a change of rule, what prompted it, and whether results had been
seen under the old rule. Results under an old rule are not mixed with new ones.

1. **TPC-H: orders and lineitem → all eight tables**, so the normalized shape
   is the whole schema. Orders and lineitem are byte for byte the files used
   before (their checksums did not move). Prompted by coverage, after results.
2. **TPC-H SF 1 removed.** It was sized only, never timed, and needed several
   gigabytes per format; it adds nothing to the web regime. After results.
3. **Public BI: first 16 384 rows → a seeded random sample of 16 384 rows**,
   because the head of a sorted table is not representative of it (above).
   After results under the head rule; the seed was fixed before any sampled
   table was measured. The head subsets are kept outside the manifest for a
   comparison, not reported as results.
4. **Two regimes declared** (above), so that the cases far past the intended
   message size are reported apart. A reporting rule; no data changed.

## How a dataset is built

A dataset is a Go package under `datasets/<name>/`:

| file | what |
|---|---|
| `fetch.sh` | downloads (or generates) the data and verifies it: `source "$(dirname "$0")/../lib.sh"`, then `fetch URL PATH` / `git_at URL COMMIT DIR` / `verify PATH...` |
| `LICENSE-NOTE.md` | the data's licence, and whether it may be redistributed |
| `types.go` | the Go structs, with `cb` tags — the one schema every format is generated from |
| `load.go` | reads the fetched files into those structs |
| `types_msgp_gen.go`, `<name>gen/` | generated by `go run ./cmd/gen <name>`; committed |

Then:

1. Add the dataset's root types to `cmd/gen/targets.go`, each with an access
   path: a dotted path to one numeric field summed over every row
   (`"Orders.Lines.ExtendedPrice"`), or `""`.
2. `tools/fetch-flatc.sh && go run ./cmd/gen <name>`.
3. Add its cases to `matrix/cases.go`. A case whose files are missing returns
   `missing(...)`, so `go test ./...` passes in a clone that has fetched nothing.
4. `COLBIN_PIN=1 datasets/<name>/fetch.sh` once, to record its checksums; commit
   `MANIFEST.sha256`.
5. `go test ./matrix -run 'Sizes/<name>' -v -timeout 0` must pass: every format
   round-trips the data, every access aggregate agrees, and no signed field
   holds a negative without `pb:"sint"`.

### Rules for the types

- **The struct is what a Go programmer would write for this data**, not what
  any format prefers. Pick the narrowest Go type that holds every value the
  column can hold per the source's own schema (int32 for a 32-bit key, not
  int64), because the fixed-width formats (Arrow, FlatBuffers) pay for width
  and the varint formats do not.
- Exact types for exact data: money and decimals as integer minor units,
  dates as integer days, timestamps as integer microseconds (or whatever unit
  the source has). A float only for a value the source holds as a float.
- A nullable column is a pointer (`*int32`, `*string`). Do not invent a
  sentinel.
- A signed column that can be negative gets `pb:"sint"`, so protobuf uses its
  zigzag encoding. The matrix test fails if one is missed.
- Supported field shapes, which every generator handles: scalars, `[]byte`,
  `*scalar`, `[]scalar`, struct, `*struct`, `[]struct`, `map[string]scalar`
  (protobuf only). A shape a generator cannot carry is not forced: that format
  is reported as n/a for the root, with the reason.
- A document that cannot be given a struct is measured on the **dynamic path**
  (`map[string]any` / `[]any`, `bindDynamic` in `matrix/`), and reported as
  such. A dataset with hand-written structs says so in its `LICENSE-NOTE.md`
  and in the paper.

### What every case reports

`go test ./matrix -run Sizes` with `COLBIN_RESULTS=results` writes:

- `sizes.csv`: per case and format, bytes, bytes per row, gzip and zstd, both at level 6,
  and round-trip status;
- `cases.csv`: per case, the rows that colbin writes as tables against lists,
  the bytes the tables account for, leaf values, colbin bytes per value, the
  schema section size and gob's steady-state stream size.
